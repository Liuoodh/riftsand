## v0.16 摇晃 / 互堵的真因：路径反复重算 + 停车位预约（已完成）

用户反馈"还是同样的问题（除了像素感外）"，说明 v0.15 改的是表现。这一版换了测量方法：
新增 `tools/walktest.mjs`，**不清空地图**，用真实开局 + 6 辆坦克逐帧采样朝向。

```
id=25  img=5  turned=248°  idleTurn=209°  ftChg=4
```

航向目标只变 4 次却转了 248°，其中 209° 发生在目标不变的帧里 —— 说明转动不是来自转向逻辑，
而是**路径被反复替换、每次指向不同方向**。

### 数字

| 指标（同场景） | v0.15 | v0.16 |
|---|---|---|
| 单辆最大转向度数 | 745° | 34–107°（5/6 辆） |
| 单辆贴图切换 | 9 | 1–2（5/6 辆） |
| idleTurn（目标不变却在转） | 209° | 0° |
| 10 车同点：最终散布 | 240–310 px | 80–125 px |
| 10 车同点：放弃订单 | 4–5 | 0 |

### 改动

1. **等待移动中的友军**：2.6 s → 8 s（原版对"挡路者有速度"根本不设上限，直接继续开）
2. **触发绕行门槛**：0.35 s → 1.0 s
3. **绕行方向校验**：新路径首段与原路径首段夹角 > 50° 换锚点
4. **`wrapAngle()`**：车体与炮塔角度约束在 (-π, π]，消除正西/正东附近的每帧振荡
5. **到位判定**：`path.length <= 1` 且目标格满 → CloseEnough
6. **停车位**：`smooth()` 单点路径合法（只拒 `!lastFound`）、`cellClaimedBy()` 预约、
   `pickParkingSpot()` 按 `距离 + 30×转角` 打分
7. **步兵 CloseEnough**：只在路点同时是订单目标时判定到达

## v0.15 车体航向 / 友军互堵 / 炮塔锁定 / 144px 素材（已完成）

用户四点反馈：**① 坦克行走时身体不断转向摇晃；② 仍然卡死，还提示被友军挡住，原版被挡住就走不了吗；
③ 炮塔一直转复位再转；④ 素材像素感太浓**。

前三条都是"症状反复出现"，说明前几版改的是表现而不是机制。这一版先写了 `tools/steertest.mjs`
把三件事量出来（直线航向翻转次数、炮塔回退次数、10 车同点到达率），再逐条对到原版的具体代码。

### 四条根因

| 症状 | 原版做法 | 我们的错误 | 修法 |
|---|---|---|---|
| 车体摇晃 | `DriveLocomotor.onNewWaypoint` 算一次航向 + `TurnTask`；直线段 `tick()` 不写 `direction` | 每帧 `atan2(路点-位置)` 再追，20px 路点抖一格就是 3° | `faceTarget` 只在路点对象变化时重算；转向改成"余量小于一步就吸附" |
| 贴图抖动 | `direction` 是离散值，天然不抖 | `Math.round` 在 22.5° 边界上两帧一跳 | `facingIndexSticky()`：6° 滞回 |
| 被友军堵死 | 先绕行到最近无障碍路点（保留后续路线）→ 步兵换子格 → 等待 2.7s → 空闲友军 `MoveAsideTask` → `findRelocationTile`（5 格）；5 次 unreachable 才 Fail | 顺序反了（先推人），绕行是"绕到最终目标"，4 轮就取消订单并弹提示 | 按原版重排；`repathAround` 保留尾部；`parkNear` 代替放弃；只有 > 6 格才报不可达 |
| 炮塔回正 | `TurretTrait.desiredFacing` 每 tick 被写，`currentTarget` 跨 tick 存活，**没有超时** | `turretAim + 2.2s 倒计时`，且索敌 0.22s 冷却期间不写目标 | 持久 `focus` 目标，无倒计时 |

### 顺带修掉的三处

- **寻路代价加单位密度惩罚**：原版用 `reservedPathNodes` 硬占格；连续移动里硬阻塞会死锁，
  改用软代价（1 + 1.6×人数，上限 6 倍），车流自然分道。
- **`repathAround` 截短路径**：只替换成"到中间路点的路径"会丢掉尾部，单位停在离目标几百像素处。
  必须 `p.concat(rest)`。
- **watchdog 阈值 18px 太紧**：目标格满了会触发 CloseEnough（清空路径），watchdog 立刻判定"停滞"并
  重新规划，单位在目的地旁边来回抽动 2.4 秒才停。阈值改成 1.8 格（CloseEnough 是 1.5 格）。

### 素材

- Blender 改为 576 渲染 → 降采样 **144**（原来是 72），图集 1152×720 / 169 KB；
- 纹理过滤 `NEAREST` → `LINEAR + mipmap`；节点显示尺寸仍是 72，由硬件降采样。
- `docs/ART-GUIDE.md` 的规格表、manifest 示例、管线说明同步改成 144。

### 四条根因

| 症状 | 根因 | 原版依据 |
|---|---|---|
| ① 车身一直摇 | 开火时把**整个车体**沿屏幕 X 平移 26px（且不管炮口朝哪，永远是屏幕 X），退回 0.18s。交火中每秒 4 次 → 看起来就是抖。 | 原版没有车体位移，只有炮管后坐 |
| ② 平面上说"无法到达" | 被友军堵住时走 `failMove → giveUpOrder`，而提示语固定是"无法抵达目标"。 | `MoveTask` 在放弃前先判 `isCloseEnoughToDest()` → `MoveResult.CloseEnough`，**这算成功** |
| ③ 队列互堵 | 每走一步都校验"目标格有没有车"。前车正在开出该格时，后车依然被拒 → 队列永久死锁 → 重算 4 次后取消订单。 | 障碍循环只在挡路者**静止**（`moveState === Idle`）时才算障碍；挡路者还在移动就 `break` 放行 |
| ④ 到了还乱晃 | 同上：到不了就反复重算/侧移；且行走动画固定 9fps，低速时履带仍在全速滚动 | `Sequences` 的播放速率跟随移动速度 |

| 通行规则 | `stepBlockedByUnit`：目标格里的车若**同向且正在开走** → 不算墙（`cos(Δface) > 0.55`）；否则按格容量/间距处理 |

### 关于"原版会不会重叠"

- **逻辑上不会**：原版 `MoveTask.canStopAtTile` 明确限制一格 3 名步兵且子格必须不同；
  我们的实现与之对齐（`subCell 0..2`，`±TILE/4`）。
- **载具**：原版 `canStopAtTile` **没有**车与车的格子容量判定，靠路径预订 + 碰撞等待链避免；
  我们额外限制"一格一辆"，只对采集车放开（卸货必须贴在一起），并给同格两车固定偏移。
- **视觉上会**：2D 精灵远大于格子（一格 56×28 屏幕像素，坦克精灵 72×72），任何等距 RTS 都会重叠。
  能修的是"两单位画在同一像素"和"站位过密"，修不了"大精灵互相遮挡"——那属于正常现象。

## 技术债

1. 避障是"质量分离 + 对冲让位 + 卡住重规划"，不是完整 RVO；极窄走廊仍可能短暂推挤 → v0.5 引入简化 RVO。
2. 卡片与 HUD 命令式刷新，条目多时仍会全量重算 → 抽成轻量数据绑定。
3. 迷雾/小地图每帧重算 128×128 纹理，低端机可降到 10Hz；物理与弹道尚未做低端机降级。
4. 场景中 `Boot` 组件以压缩 UUID 挂在 `App` 节点，脚本改名/迁移目录会导致 UUID 变化 → 需在编辑器重新挂载。
5. 建筑队列只有 1 格，连续造墙/连续补建筑时操作偏多 → v0.4 支持队列 3 格与拖拽放置。
