# 素材制作规格书（v0.10）

这份文档回答四个问题：**要做哪些素材、每张多大、用什么工具做、做完放在哪以及怎么验证能读进来**。

结论先放在最前面：

- 图片格式统一用 **PNG-32（带 alpha）**，不要求 SHP。SHP 我们也读（`assets/Shp.ts`），但那是给「直接接 mod 素材」用的，不是你要走的路径。
- 组织方式用 **一张图集（atlas）+ 一个 JSON（manifest）**。图集是给渲染用的，JSON 是给代码索引用的。
- 尺寸以「格子」为基准换算。1 格 = 32 世界像素，投影后菱形 **56×28** 屏幕像素。
- 先做 1 个单位 × 8 方向 × 1 帧，能进游戏、朝向对、比例对，再批量生产。**不要一次性画 30 个单位。**
- 不要用红警原版素材。仓库里那个 `RedAlert2-Android-main` 是 GPL 代码参考，**不含美术**，从原版游戏里提取素材属于侵权。

## 1. 坐标系与朝向（最容易做错的一条）

### 1.1 格子与屏幕

| 概念 | 数值 |
|---|---|
| 逻辑格 | 32 × 32 世界像素 |
| 屏幕菱形 | **56 × 28** px（2:1） |
| 地形每层抬升 | 16 px |
| 单位脚底锚点 | 精灵画布中心（x = w/2, y = h/2） |

一个单位站在格中心时，它的**脚底**（履带接地面、人的脚）应该正好落在画布中心。

### 1.2 8 方向顺序

代码里的换算（`render/Frames.ts`，公式抄自原版）：

```
facingIndex(deg) = round(((deg - 45 + 360) % 360) / 360 * 8) % 8
facingDeg(i)     = (i + 1) * 45
```

在**屏幕**上，8 帧依次是：

| 帧号 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 朝向 | 上 | 左上 | 左 | 左下 | 下 | 右下 | 右 | 右上 |
| 世界角度 | 45° | 90° | 135° | 180° | 225° | 270° | 315° | 0° |

也就是：**从「朝上」开始，屏幕逆时针排一圈**。

做错的典型症状：单位绕圈走时像在横着滑；炮口永远偏 45°；往后走时车头朝前。

### 1.3 炮塔必须单独一张

车体（hull）和炮塔（turret）分开画、分开导出。原因：炮塔要独立转向，如果合成一张，缓存会从「8 方向 × 4 帧 = 32 张」膨胀到「8 × 4 × 8 = 256 张」。

炮塔画布与车体同尺寸，锚点也一样（车顶中心大致重合画布中心）。

## 2. 单位素材清单

### 2.1 一张表看懂「每个单位要几张」

| 项目 | 尺寸 | 数量 | 必需 |
|---|---|---|---|
| 车体 Ready | 72 × 72 | 8（8 方向 × 1 帧） | ✅ |
| 车体 Walk | 72 × 72 | 32（8 方向 × 4 帧） | ✅ |
| 炮塔 | 72 × 72 | 8（8 方向 × 1 帧） | 有炮塔的单位 |
| 开火 FireUp | 72 × 72 | 16（8 × 2 帧） | 推荐 |
| 死亡 Die1 | 72 × 72 | 32（8 × 4 帧） | 推荐 |
| **小计（最小）** | | **40 张/单位** | |
| **小计（完整）** | | **96 张/单位** | |

帧率：Walk **9 fps**、FireUp 14 fps、Die1 7 fps。循环由代码控制，你只要按顺序排帧。

### 2.2 图集怎么排

推荐**每个单位一张图集**，横向排：

```
row 0: Ready   [0..7]                      8 帧
row 1: Walk    [0..7] [8..15] [16..23] [24..31]   ← 按「帧」分组，不是按方向
```

两种都行，只要 JSON 里标清楚。我们推荐**按方向分组**（更符合原版 SHP）：

```
Walk: 方向 0 的 4 帧连续, 方向 1 的 4 帧连续, ...
帧号 = start + facingMult * facingIndex + animFrame
```

这样 `frameIndex` 的换算和原版一致，将来接真 SHP 时零改动。

> ⚠️ **图集是「线性 32 帧」，不是「4 行 × 8 列」的语义。** 因为 `frame = start + 4 × facing + anim`，
> 方向 0 的 4 帧落在 index 8–11（= 第 2 行前 4 格），方向 1 的 4 帧落在 12–15（第 2 行后 4 格）……
> `art/templates/README.md` 里写的「行 1–4 = Walk 1–4；列 = 方向」在这个公式下不成立，
> 按行填模板会得到「每帧只有一个方向」的错图。**以 `render/Frames.ts` 的公式为准**，
> 把 32 帧当成一条连续序列，按 `8 + 4 × facing + anim` 落格。`art/units/rampart.png` 就是这么排的。

### 2.3 各单位的差异

| 类型 | 说明 |
|---|---|
| 步兵 | 8 方向必须画（能看到正/背/侧）；Walk 建议 6 帧（步态更顺），FireUp 1 帧即可 |
| 车辆 | 8 方向；履带/轮子要在 Walk 的 4 帧里滚动起来 |
| 悬浮/气垫 | 8 方向，且**不需要减速表现**（地形速度表里 hover = 1.0） |
| 飞机 | 只需要 1 个方向（代码会旋转节点），但要有 bank（压弯）姿态 |
| 采集车/基地车 | 同车辆；采集车建议加 1 帧「卸货」状态（可选） |

### 2.4 阵营色怎么处理

**不要**把阵营色画死。留出 3 个可替换色槽即可：

- 车体主色用中性灰（`#4b5461` 附近），不要用纯队色；
- 队色条/徽记用一个单独图层，导出时提供 **BU 橙 / DS 青** 两版，或者只导出灰度图，代码里叠 `teamBU/teamDS` 色调。

代码目前的做法是：车体用中性色，队色画在车顶一条带 + 炮塔口，全部由 `PAL.teamBU` / `PAL.teamDS` 上色。

## 3. 建筑素材清单

### 3.1 画布尺寸（按占地格子数）

| 占地 | 画布 | 说明 |
|---|---|---|
| 1×1（炮塔、围墙） | 64 × 64 | 菱形底 26×13 |
| 2×2（电厂、兵营） | 96 × 96 | 底 52×26 |
| 3×3（精炼厂、工厂） | 128 × 128 | 底 78×39 |
| 4×4（指挥核心、超武） | 160 × 160 | 底 104×52 |

锚点：**菱形底面中心** = 画布中心。建筑向「上」生长（屏幕上方），所以画布上半部分要留足高度。

参考高度：普通建筑大约 `11 + 3×size` px 高（size=4 → 23px 的墙体），指挥核心 `22 + 3×size`。画超过这个高度也可以，代码按 `progress` 拉伸的是整体高度，不会裁切。

### 3.2 四态（每种建筑都要）

| 状态 | 触发条件 | 画面要求 |
|---|---|---|
| normal | HP > 50% | 完整、干净 |
| damaged | HP ≤ 50% | 焦痕、裂纹、局部破损、少量烟 |
| buildup | 刚放置，0.6–20 秒 | 可以是同一张图 + 脚手架（代码已画），也可以给 4 帧「升起」序列 |
| ruined | 被摧毁 / 卖出 | 焦黑地基 + 碎块（代码已画程序化废墟，接图后替换） |

同一建筑的 4 态可以是同一张图集的不同行，也可以是 4 张独立 PNG。建议一个建筑 `256×256` 的图集，装 4 个状态。

### 3.3 建筑动画（可选，做完加分）

原版建筑有 `ActiveAnim`（精炼厂烟囱冒烟、雷达转、超武充能）。要做的话：

- 每个建筑 1 个 32×32 或 48×48 的小序列，4–8 帧循环；
- 在 manifest 里标注 `activeAnim: { x, y, frames, rate }`，`x/y` 是相对建筑锚点的偏移。

## 5. 工具链

### 5.1 画图

| 工具 | 适用 | 说明 |
|---|---|---|
| **Aseprite**（付费，约 $20） | ✅ 首选 | 图层、tag 导出、「Export Sprite Sheet → JSON Array」正好是我们需要的结构；也有 CLI 可批处理 |
| **LibreSprite / Piskel**（免费） | ✅ | Aseprite 的开源分支，功能够用 |
| **Krita**（免费） | ✅ | 手绘风更自由，但没有帧 tag 导出，需要手工排图 |
| **Photoshop / Affinity** | ✅ | 适合非像素风的高分辨率重绘；导出时用脚本切片 |
| **Blender**（免费） | 推荐 | **做等距车辆/建筑最省力的办法**：建低模 → 正交相机 45° → 渲染 8 个朝向 → 抠图。原版的红警车辆本质就是这么来的（3D 渲染成 8 向精灵） |

如果你想让游戏「像红警」，**Blender 渲染 8 方向**比手绘更快也更一致：一个模型转 8 次，光照统一。

### 5.2 拼图集

Aseprite CLI 示例（每个单位跑一次）：

```bash
aseprite -b tank.aseprite \
  --sheet tank.png \
  --data tank.json \
  --format json-array \
  --split-tags \
  --trim --extrude 1
```

或者交给 ImageMagick 拼：

```bash
montage ready_*.png walk_*.png -tile 8x -geometry +0+0 -background none tank.png
```

`--extrude 1` 很重要：图集相邻帧之间留 1px，避免采样时串色。

### 5.3 地图

- **布局用 `tools/mapeditor.html`**（浏览器里直接开，无需安装）：涂地形/高度/阻挡、放矿点和出生点，导出 JSON。
- 地形瓦片本身仍然是 PNG 或 TMP；编辑器只负责「哪一格放什么」。
- 导出后 `node tools/mapbuild.mjs` 校验并打包，`node tools/maptest.mjs` 进游戏验收。
- 完整格式、素材数量、设计准则、验收标准：见 [`MAP-GUIDE.md`](./MAP-GUIDE.md)。

### 5.4 真素材接入（Blender 批次 → 游戏）

图集画完/渲染完后，**三步进游戏**：

```bash
node tools/artimport.mjs    # 合并 art/manifest*.json + 拷图到 project/assets/resources/art
#  … 构建（CocosCreator --build）
node tools/artcheck.mjs     # 可选：打印「引擎朝向 N → 图集帧 M」对照表
```

**目录约定**

| 位置 | 作用 |
|---|---|
| `art/units/*.png`、`art/manifest.<批次>.json` | 你在仓库根的工作区（Blender 直接往这里输出） |
| `project/assets/resources/art/**` | 运行时真正加载的副本，由 `artimport` 生成，**不要手改** |
| `art/templates/**` | 空白模板，`artimport` 会跳过（否则会把占位图当成品导进去，把程序化美术覆盖成空白） |

**为什么必须放 `resources/`**：小游戏打包只会带上 `assets/resources` 下被引用的资源；放在普通
`assets/` 的 PNG 不会进包，运行时是空的。

**朝向与排版（已经踩过的坑）**

- 帧序必须是 `start + animFrame × facings + facing`（朝向是最内层，8 张一行）。
- 朝向表：`0 上 / 1 左上 / 2 左 / 3 左下 / 4 下 / 5 右下 / 6 右 / 7 右上`，与引擎
  `facingIndex()` 一一对应，**不需要** `dirOffset`。若某批渲染的起点不同，在 manifest 里加
  `"dirOffset": n` 即可，不用改代码。
- 锚点：帧中心 = 车体触地点（`anchor: 36,36`），这样单位站在格心、不会浮空。
- 炮塔单独一张、与车体同一锚点；`EntityView` 用同一变换叠上去，后坐力位移两者一致。

**没画完的单位**会自动退回程序化画笔，所以可以逐个单位替换，不会出现空白单位。
`assettest.mjs` 会校验：帧数够不够、图集尺寸是否是帧宽高的整数倍、缺哪一帧。

### 5.4 Blender 管线（本仓库已实现，可复用）

用 `ahujasid/blender-mcp` 的 Blender 插件把 `bpy` 脚本送进**正在运行的 Blender** 执行，
产出 PNG 图集。不需要 uv / Python 依赖，Blender 自带 numpy 就能做降采样和拼图。

```bash
# 1) 插件：把仓库里的 addon.py 拷到用户插件目录，Blender 里启用（或 Python 里 addon_utils.enable）
#    C:\Users\<you>\AppData\Roaming\Blender Foundation\Blender\5.2\scripts\addons\blender_mcp.py
# 2) 插件面板 Connect -> 监听 127.0.0.1:9876
# 3) 跑构建脚本（走同一个 execute_code 通道）
python tools/blender/bridge.py run tools/blender/rampart_build.py
```

| 文件 | 作用 |
|---|---|
| `tools/blender/bridge.py` | 最小 socket 客户端，`run <脚本>` / `code "<片段>"` / `ping` |
| `tools/blender/blib.py` | 场景/材质/几何/渲染/降采样/拼图集的公共函数 |
| `tools/blender/rampart_build.py` | 城墙主战坦克：建模 + 48 帧渲染 + 两张图集 |
| `tools/blender/inspect_atlas.py` | 6× 放大 + 锚点十字线，检查朝向与锚点 |
| `tools/blender/inspect_hires.py` | 288px 原图合成审阅（车体 + 炮塔叠一起） |
| `art/blender/rampart.blend` | 场景源文件，改模型从这里改 |

管线里的固定约定（和本文档其余部分一致，别改）：

- 相机正交、俯角 **30°**（`rotation_euler.x = 60°`），看向世界原点 —— 原点即接地面中心，直接落在画布中心；
- 朝向 i 的渲染 = 模型绕 Z 转 `90° + 45°i`，得到「上 → 左上 → … → 右上」的顺序；
- 光照固定在世界空间（左上主光 + 冷补光 + 青色轮廓光），只转模型不转灯；
- 渲染 288×288（4 倍超采样）→ 盒式降采样到 72 → 加 1px 暗描边 → 按线性帧号拼图集；
- 履带用程序纹理（`ShaderNodeTexWave`）在物体坐标上平移，四帧各移 1/4 齿距。

新增单位的最小改法：复制 `rampart_build.py`，改 `build_hull` / `build_turret` 的尺寸，其余不用动。

## 6. manifest：代码怎么找到你的图

每套素材一个 JSON，放在仓库根的 `art/` 下。最小可用版本：

```json
{
  "version": 1,
  "palette": "art/pal/sand.pal",
  "units": {
    "rampart": {
      "image": "art/units/rampart.png",
      "frame": { "w": 72, "h": 72 },
      "anchor": { "x": 36, "y": 36 },
      "facings": 8,
      "sequences": {
        "ready":   { "start": 0,  "frames": 1, "rate": 0 },
        "walk":    { "start": 8,  "frames": 32, "rate": 9 },
        "fireUp":  { "start": 40, "frames": 16, "rate": 14 },
        "die1":    { "start": 56, "frames": 32, "rate": 7 }
      },
      "turret": {
        "image": "art/units/rampart_turret.png",
        "frame": { "w": 72, "h": 72 },
        "start": 0,
        "frames": 8
      }
    }
  },
  "buildings": {
    "core": {
      "image": "art/buildings/core.png",
      "frame": { "w": 160, "h": 160 },
      "anchor": { "x": 80, "y": 80 },
      "states": { "normal": 0, "damaged": 1, "ruined": 2, "buildup": 3 }
    }
  },
  "tiles": {
    "image": "art/terrain/sand.png",
    "frame": { "w": 56, "h": 28 },
    "variants": { "sand": [0, 1, 2, 3], "dune": [4, 5], "rock": [6, 7], "crystal": [8] }
  }
}
```

规则：

1. `start` 是**图集里的帧序号**（按行优先，从 0 开始）；
2. 帧序号换算沿用原版：`frame = start + facingMult × facingIndex + animFrame`，`facingMult = 该方向的帧数`；
3. `anchor` 是脚底/底面中心在单帧画布里的坐标；默认就是画布中心，只有美术出血不对称时才需要改；
4. 路径写相对仓库根目录。

## 6.1 我们直接能读的格式

| 格式 | 状态 | 用途 |
|---|---|---|
| PNG（任意尺寸） | ✅ 原生 | 图集、单图、瓦片 |
| PNG + JSON（Aseprite/TexturePacker json-array） | ✅ 已实现解析思路，需按 manifest 映射 | 图集 |
| SHP + PAL | ✅ 已实现（含 LCW 解压、阵营 remap） | 直接吃 mod 素材 |
| TMP | ✅ 已实现（元数据 + 菱形扫描线展开） | 地形瓦片 |
| VXL/HVA | ⬜ 未实现 | 体素车辆，优先级低 |
| PSD / AI / ASE | ⬜ 不读 | 请导出 PNG |

## 7. 素材从哪来（四条现实路线）

| 路线 | 成本 | 质量 | 风险 |
|---|---|---|---|
| **1. 自己画**（Aseprite） | 时间 | 可控 | 车辆 8 方向 × 4 帧非常耗工；建议先做 1 个单位验风格 |
| **2. Blender 低模渲染** | 学习成本 1–2 天 | 一致性好、能做 8 方向 | 需要建模基础；渲染出来要手工修边 |
| **3. 买/下 CC0 等距素材包** | 0–$50 | 参差 | 一定要看许可证；「免费」不等于「可商用」；风格要统一 |
| **4. AI 生成 + 手工修** | 低 | 不稳定 | 8 方向一致性极差，通常只能当概念图，不能直接进游戏 |

我的建议：**先用 Blender 做 1 辆坦克、1 栋建筑、1 种地面**，跑通「素材进游戏」这条链路，确认比例和观感，再决定量产方式。

- Blender 导出要点：正交相机、俯角 **30°**（约 `rotation_euler.x = 60°`）、8 个朝向每 45° 一张、渲染 256×256、关闭阴影（影子由代码画）、输出 PNG 带 alpha。
- 参考比例：单位车体约占 33×21 px（72 的画布），建筑 4×4 约占 104×52 px 底面。

---

## 8. 最小起步路径（建议按这个顺序）

1. **1 个单位 × 8 方向 × 1 帧**（Ready）：验证朝向顺序和比例；
2. 加 Walk 4 帧：验证帧率、履带滚动；
3. 做 1 栋建筑 4 态：验证建造动画、受损、废墟；
4. 做 1 组地面瓦片（沙地 ×4 + 沙丘 ×2）：验证拼接有没有缝；
5. 铺开到全部单位与建筑。

每一步做完直接丢进 `art/`，我改 `unitBodyFrame()` / `drawBuilding()` / `TerrainView.paint()` 三处即可接入，`EntityView` 不用动。

## 9. 交付前自检（`tools/assetcheck.mjs`）

```bash
node tools/assetcheck.mjs                 # 用示例 manifest 自检
node tools/assetcheck.mjs assets/art      # 检查你自己的素材目录
```

它会检查：

- manifest 是否存在、字段是否齐全；
- 引用的图片是否存在、能否读出宽高；
- 画布尺寸是否是 `frame.w × frame.h` 的整数倍；
- 每个 sequence 的 `start + frames × facings` 是否超出图集帧数；
- 8 方向是否配齐（缺哪几个会列出来）；
- 给出「还差多少张」的清单。

缺文件名规范建议：

```
art/
  manifest.json
  units/<id>.png            # 车体（8 方向 × N 帧）
  units/<id>_turret.png     # 炮塔
  buildings/<id>.png        # 4 态
  terrain/<theater>.png     # 瓦片图集
  fx/<name>.png             # 特效序列
  ui/<name>.png             # 图标
  manifest.json
```
