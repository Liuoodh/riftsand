# 美术素材制作指南（ART GUIDE）

> 面向：要给这个项目画**自己的**单位 / 建筑 / 地形的人。
> 前提：不用现有的程序化矢量图。全部走**位图帧 + 图集**。
> 本文给的尺寸、朝向顺序、锚点、帧率都与代码里的实现一一对应，照做就能接上。

---

## 0. 先做一个决定：SHP 还是 PNG？

| | SHP + PAL（原版格式） | PNG 图集 + JSON（推荐） |
|---|---|---|
| 色深 | 8 位索引，**最多 256 色**，无半透明渐变 | 32 位 RGBA，随意 |
| 工具 | OS SHP Builder / XCC Utilities（老旧、仅 Windows） | Aseprite / Photoshop / Krita 都行 |
| 互通 | 能与红警 mod 工具链互通 | 不能 |
| 体积（微信小游戏） | 小 | 中（可优化） |
| 我们的管线 | **已实现解析**（`assets/Shp.ts`） | 需补 30 行 loader |

**建议**：原创项目用 **PNG 图集**。SHP 是 1997 年的格式，它的唯一优势是“能和现成 mod 素材混用”——我们没有这个需求，却要承担 256 色和工具链老旧的代价。

**但帧的组织方式必须照抄原版**：8 方向、帧序列、固定帧率、脚底锚点。这才是“红警那种感觉”的来源，不是文件后缀。

> `assets/Shp.ts` 保留着，将来若要接 mod 素材，`frameFromShp()` 直接可用。

## 1. 坐标系速查（照这个画不会错）

```
ISO_W = 56 px      菱形宽
ISO_H = 28 px      菱形高（正好 2:1）
HEIGHT_PX = 16 px  每提升一层地形，向上抬 16px
```

- 一个地块 = **56 × 28** 的菱形。
- 屏幕上方 = 世界“北”，屏幕左下 = “西南”。
- 单位站在菱形**中心**。

---

## 2. 朝向顺序（最容易做错的一处）

代码里的公式是：

```ts
facingIndex(deg) = round(((deg - 45 + 360) % 360) / 360 * 8) % 8
```

把它反解出来，**图集里 8 个方向必须按这个顺序横排**：

| 帧序号 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 世界角度 | 45° | 90° | 135° | 180° | 225° | 270° | 315° | 0° |
| 方位 | 东北 | 北 | 西北 | 西 | 西南 | 南 | 东南 | 东 |

即：**从东北开始，逆时针排一圈，最后一格是正东。**

> 画错顺序的症状：单位绕圈走时会“倒着滑行”、炮口永远偏 45°。
> 验证方法：让单位绕一个圆走一圈，8 个朝向应该依次出现且没有跳变。

## 3. 单位规格

### 3.1 画布与锚点

| 项 | 值 | 说明 |
|---|---|---|
| 单帧画布 | **72 × 72** | 与 `FRAME_W/FRAME_H` 一致 |
| 锚点 | 画布中心 `(36, 36)` | 即单位“脚下”的世界坐标点 |
| 车体朝向 | 画布中心偏下 | 车体椭圆大致落在 y ∈ [26, 46] |

72×72 足够放下一辆重坦（投影后约 50×36）。做更大的单位（MCV、飞机）也别超过这个尺寸，否则要改 `FRAME_W/FRAME_H` 并重建缓存。

### 3.2 帧序列

| 序列 | 帧数 | 帧率 | 说明 |
|---|---|---|---|
| `Ready` | 1 | — | 待机 |
| `Walk` | 4 | 9 fps | 移动循环，履带滚动 / 步态 |
| `FireUp` | 2 | 14 fps | 开火前摇（可选） |
| `Die1` | 4 | 7 fps | 死亡（可选） |

**每个方向都要有独立的 `Walk` 4 帧** → 一个单位 = `8 方向 × (1 + 4) = 40 帧`。

图集排布（行 = 序列，列 = 方向 × 帧）：

```
第 0 行：Ready  → 8 帧（每个方向 1 帧）
第 1 行：Walk   → 32 帧（方向0的4帧、方向1的4帧 …）
```

即行内顺序是 `方向 → 该方向的帧`，与 `startFrame + perFacing * dir + frame` 的公式一致。

### 3.3 炮塔必须单独一张

有炮塔的车辆，**车体与炮塔分开画**：

| 部件 | 内容 | 帧数 | 建议画布 |
|---|---|---|---|
| 车体 `hull` | 底盘、履带、车顶、队伍色条 | 8 方向 × 5 帧 | 72 × 72 |
| 炮塔 `turret` | 炮塔座 + 炮管 | 8 方向 × 1 帧 | 40 × 40 |

原因：炮塔独立转向。若把炮塔烘进车体，缓存会从 40 张涨到 320 张/单位。

炮塔的锚点在画布中心，对应车体画布里的 `(36, 36 - 车体高)`。

### 3.4 步兵

- 同样 8 方向 × 5 帧，但**左右两个半周可以镜像**：方向 0/1/2 与 4/5/6 互为镜像时，只画一半（3+1 个方向），运行时 `scaleX = -1`。
  代码已支持翻转（`EntityView` 里按 `cos(角度) < -0.15` 判翻转）。
- 步兵锚点在**脚底**，不是画布中心——把人物画在 `(36, 12)` 到 `(36, 60)` 之间。

## 4. 建筑规格

建筑占 `size × size` 格，投影后是一个菱形：

| 项 | 值 |
|---|---|
| 菱形宽 | `size × 56` |
| 菱形高 | `size × 28` |
| 画布大小 | 菱形宽 × (菱形高/2 + 立面高)，建议 `(size×56) × (size×28 + 64)` |
| 锚点 | 菱形中心 `(画布宽/2, 立面高 + 菱形高/4)` |

### 画法顺序（与代码一致）

1. 地面阴影（菱形，向下偏 2–3px，黑色 25%）
2. 左墙（菱形左下边向下挤出 `H`）
3. 右墙（菱形右下边向下挤出 `H`，比左墙暗 20%）
4. 顶面菱形
5. 屋顶细节（按建筑类型）
6. 队伍色条（顶面靠下边缘）

| 建筑 | 建议立面高 `H` | 屋顶特征 |
|---|---|---|
| 指挥核心 | 22 + size×3 | 大圆环 + 天线 |
| 电厂 | 11 + size×3 | 两块倾斜光板 |
| 矿厂 | 11 + size×3 | 3 个储罐 + 烟囱 |
| 兵营 | 11 + size×3 | 横向条纹 + 门洞 |
| 工厂 | 11 + size×3 | 卷帘门 + 吊臂 |
| 机场 | 11 + size×3 | 圆环跑道 |
| 防御塔 | 11 + size×3 | 炮座 + 炮管 |
| 超武 | 22 + size×3 | 圆顶 + 天线 |

### 四态

原版每个建筑主图有 4 帧：**正常 / 受损 / 进驻 / 废墟**。
建议图集按 `4 帧 × 2 阵营` 排，运行时按血量与状态取帧。

## 5. 地形瓦片

| 项 | 值 |
|---|---|
| 单块尺寸 | **56 × 28**（若沿用红警原版 60×30，需要按 56/28 缩放，会有 7% 拉伸） |
| 图集 | 按“地形种类 × 变体”排，建议 8 列 |
| 需要的种类 | 沙地 ×4、沙丘 ×4、岩石 ×3、矿脉 ×3、边缘过渡 ×8 |

**关键要求**：每块瓦片必须是**满幅菱形**（四角正好落在 56×28 的四个顶点），不要留透明边，否则拼接会露缝。

若想沿用原版 TMP（60×30 + 高度 + rampType），`assets/Tmp.ts` 已能读出 `zHeight` / `terrainType` / `rampType`，直接填 `Terrain.level` 与 `.kind`。

## 6. 调色板与阵营色

即使改用 PNG，也建议**统一一套色板**，否则两个阵营的视觉会分裂。

原版规则（我们已实现）：

- 索引 **16..31** 是阵营色槽位，共 16 档亮度。
- 亮度因子：`63, 59, 55, 52, 48, 44, 41, 37, 33, 30, 26, 22, 19, 15, 11, 8`
- 写入公式：`slot = floor(base / 255 * factor * 4)`

如果你用 PNG 全套全彩，就**把阵营色单独抽成一层**：单位图只画灰阶底盘，队伍色条用代码叠加（当前就是这么做的，`drawHull` 里那条 `tc` 描边）。

## 7. 制作流程

### 7.1 推荐工具

| 用途 | 工具 |
|---|---|
| 像素画 / 动画帧 | **Aseprite**（付费，最顺手）、Krita（免费）、GraphicsGale（免费） |
| 批量导出 | Aseprite 的 Export Sprite Sheet，或 Photoshop 的动作批处理 |
| 图集打包 | **TexturePacker**、Aseprite 自带、或 `free-tex-packer` |
| 调色板 | Aseprite 的 palette 面板，导入 `.gpl` / `.pal` |

### 7.2 步骤

1. **定色板**：新建 32 色板（含 16 档阵营色），全项目复用。
2. **画一个方向**：先画“东”（帧序号 7）。确认脚底/中心锚点。
3. **复制旋转**：Aseprite 里按 45° 旋转复制，再手工修**明暗**（等距光源固定从左上来）。
4. **出 4 帧走路**：位移履带纹路 / 摆腿，幅度 1–2px 就够。
5. **导出**：每帧 72×72，文件名 `{unitId}_{dir}_{seq}{frame}.png`。
6. **打包图集**：按第 3.2 节的行列排布，生成一张 PNG + 一份 JSON。
7. **写 manifest**（见下）。
8. **接进项目**：把 manifest 放进 `project/assets/resources/units/`，运行时 `resources.load` 读 PNG 与 JSON，用 `SpriteFrame.rect` 切帧。

### 7.3 manifest 格式（建议）

```json
{
  "id": "rampart",
  "atlas": "units/rampart.png",
  "frameW": 72,
  "frameH": 72,
  "anchor": [36, 36],
  "facings": 8,
  "sequences": {
    "ready": { "row": 0, "frames": 1, "rate": 0 },
    "walk":  { "row": 1, "frames": 4, "rate": 9 }
  },
  "turret": { "atlas": "units/rampart_turret.png", "anchor": [20, 20] }
}
```

与 `render/Frames.ts` 的 `SEQUENCES` 字段一一对应，加载时直接覆盖即可。

## 8. 接进项目（代码侧）

当前 `assets/Assets.ts` 的入口是：

```ts
unitBodyFrame(def, faction, dir8, frame): SpriteFrame | null
```

要接 PNG 图集，只改这一个函数的内部：

```ts
// 之前：CanvasPen 烘焙
// 之后：
const sheet = SHEETS.get(def.id);              // 启动时 resources.load 好的
return sheet.frame(dir8, frame);               // 内部用 SpriteFrame.rect 切片
```

`EntityView`、`Frames.ts`、炮塔叠加逻辑**全部不用改**。这就是这版把渲染换成 Sprite 的意义。

同样的替换点还有两个：

| 用途 | 函数 | 替换成 |
|---|---|---|
| 单位车体 | `unitBodyFrame()` | 图集切片 |
| 建筑 | `Art.drawBuilding()` | 4 态图集切片（改成 Sprite 渲染） |
| 地形 | `TerrainView.paint()` | 瓦片图集平铺 |

## 9. 常见错误

| 症状 | 原因 |
|---|---|
| 单位“倒着滑行” | 8 方向顺序错了（必须从东北开始逆时针） |
| 单位悬空 / 陷进地面 | 锚点没放在画布中心，或步兵锚点没放在脚底 |
| 拼接处有黑缝 | 瓦片菱形没画满，或留了 1px 透明边 |
| 阵营色不跟着变 | 队伍色画进了位图里，应该留给代码叠加 |
| 走路动画抽搐 | 帧数不是 4，或帧率与 `SEQUENCES.walk.rate` 不一致 |
| 换素材后全都变白 | 图集 UV 错了：`SpriteFrame.rect` 与 `originalSize` 必须同时设（我们踩过这个坑） |

---

## 10. 最小起步建议

不要一次做完 40 帧。按这个顺序推进，每一步都能看到效果：

1. **1 个单位 × 1 个方向 × 1 帧**（静止坦克）→ 验证锚点与比例。
2. 补到 **8 方向 × 1 帧** → 验证朝向顺序。
3. 补 **Walk 4 帧** → 验证帧率与循环。
4. 画 **1 种地形瓦片** → 验证拼接。
5. 画 **1 个建筑 4 态** → 验证四态切换。
6. 全量铺开。

到第 3 步就能判断“这套美术方向对不对”，成本最低。
