# 地图制作指南（v0.12）

> 这份文档回答三个问题：**一张地图由什么组成**、**要准备哪些素材**、**怎么把它做出来并验收**。
>
> 配套代码：`project/assets/scripts/world/MapData.ts`（格式）、`world/Maps.ts`（编译产物）、
> `tools/mapeditor.html`（编辑器）、`tools/mapgen.mjs`（起始图生成）、`tools/mapbuild.mjs`（校验 + 打包）、
> `tools/maptest.mjs`（进游戏验收）。

---

## 0. 一分钟版本

```bash
# 1. 在浏览器里画（不需要装任何东西，双击打开）
tools/mapeditor.html

# 2. 导出 JSON，放进 assets/maps/
#    3. 校验 + 打包（会拒绝坏图，并告诉你哪里坏）
node tools/mapbuild.mjs

# 4. 进游戏跑一遍，确认能打
node tools/maptest.mjs
```

`mapbuild` 通过后地图就出现在主界面的「战场」列表里了。

## 1. 一张地图由什么组成

红警的一张 `.map` 文件里，地面是 **一张 80×80 的瓦片表**，每格记录「用哪块图、在第几层高度、是什么地表类型」，另外再挂
overlay（树/石头/箱子）、建筑、单位、路径点这些清单。我们的地图格式就是这张表的可读版本 —— **六个数组，每格一个值**：

| 字段 | 取值范围 | 决定什么 | 对应原版 |
|---|---|---|---|
| `land` | 0 平地 / 1 沙丘 / 2 道路 / 3 矿脉 / 4 水域 / 5 岩石 | 能不能走、走多快、寻路代价 | `LandType` + `SpeedType` 速度表 |
| `height` | 0–3 | 高地、坡、悬崖、俯视优势、单位抬升 | TMP 的 `zHeight` / `level` |
| `tiles` | 0–65535 | **只影响画面**：这一格用图集里第几号瓦片 | TMP 的 tile 编号 + `subTile` |
| `blocked` | 0/1 | 地表能走、但这格是墙（栅栏、残骸、隐形墙） | `OverlayPack` 里的可阻挡物件 |
| `overlay` | 物件列表 `{kind,tx,ty,block?}` | 站在地面上的东西：灌木 / 岩石 / 箱子 | `[OverlayPack]` / terrain objects |
| `ore` | 点列表 `{tx,ty,amount}` | 矿点位置和储量，周围自动铺矿 | `Tiberium` overlay + `OverlayDataPack` |
| `spawns` | 两个点 | 双方基地中心，基地建筑按它摆 | `[Waypoints]` 的 0/1 号点 |

**关键分离**：`land` 管玩法，`tiles` 管画面。同一格「平地」可以画成龟裂土、细沙、碎石地，
玩法完全一样。这正是红警能做出几十种地貌却只有一套速度表的原因 —— 也让美术可以随时换皮而不动关卡逻辑。

数组用 RLE 压缩（`[值, 重复次数, 值, 重复次数, ...]`），一张 80×80 的图 JSON 大约 20–25 KB。

### 1.3 六个数组够不够？

按"地面 / 高度 / 画面 / 阻挡 / 资源 / 出生点"分，**六个数组是够的**；真正需要单独一层的是**地面上的物件**，
而它这一版已经补上了（`overlay`）。逐项对照：

| 你想要的地形效果 | 用什么表达 | 够吗 |
|---|---|---|
| 沙地/岩地/泥地/盐碱/公路/水面……几十种"地表长相" | `land`（玩法）+ `tiles`（画面） | ✅ 够。**数量不受数组限制，受图集大小限制**：`tiles` 是 16 位，能索引 65536 个瓦片 |
| 高台、坡、悬崖 | `height` 0–3 + 相邻差 ≥2 即悬崖 | ✅ 够（4 层对 RTS 足够；原版是 0–14，但真正用到的落差很少超过 3） |
| 同一种地的不同"拼角"（沙地接岩石的内凹/外凸/四角） | `tiles` 的编号 | ✅ 够。做法是把"沙→岩"的 16 种边角各占一个 tile id，铺图时按邻格自动选号 |
| 树、灌木、石头、箱子、油桶、残骸 | `overlay` | ✅ 这一版新增（可设 `block` 阻挡） |
| 弹坑、履带痕、血迹（纯贴地装饰） | `overlay` 里 `kind` 后再加一类即可 | ⚠️ 结构就绪、渲染未接（贴地装饰要参与"每帧都在动"的排序，晚一步做） |
| 桥（跨水/跨悬崖，双层通行） | 需要**两层地面 + 上下层通行规则** | ❌ 不够。这是唯一真正超出现有格式的东西，等有水域地图再做 |
| 可破坏的地形物件（能被炸掉的树/墙） | `overlay` + 血量 | ❌ 结构能放，但没有"物件受伤"的运行时 |
| 触发区、出生波次、剧本 | 独立字段 | ❌ 还没做，属于关卡脚本 |
| 地图尺寸 128×128 / 非正方形 | `size` 字段 | ⚠️ 格式支持，引擎侧 `MAP_TILES` 是常量，要改得动一批数组尺寸 |

**结论**：你现在想做"各种地形各种地图"，六个数组 + `tiles` 编号 + `overlay` 完全够用；
真正的瓶颈不是格式，是**图集**（下面第 2 节）和**过渡瓦片的自动选号**（第 6 节）。桥和脚本是后续两件事。


### 1.1 尺寸

- 世界 80×80 格，每格 32 世界像素；等距投影后每格画成 **56×28 像素的菱形**。
- 一屏（1280×720，默认缩放）大约看到 26×18 格。整图横跨 4480 屏幕像素。
- 为什么不做 128×128：手机端 3 倍图下整图纹理是 128×56×128 → 21 万像素宽，超纹理上限；
  而且 80×80 已经够让一支坦克连开 20 秒才到中点。**加大地图先加大格子密度，不要先加大边长。**

### 1.2 高度怎么读

`height` 是**每格一个整数层**，渲染时四个角取相邻四格的平均值，所以 1 层的落差会自动变成一格宽的斜坡 ——
这就是原版 `rampType` 的效果。因此：

- 想让高台能上去 → 在边上留一格 `height = 高台 - 1` 的过渡；
- 想让高台是悬崖 → 直接写相邻的 2 层差，不要留过渡（±1 层是可通行的，±2 层走不上去）；
- `height ≠ 0` 的格子**仍然可通行**，只是单位会被抬起来。真正挡人的是 `land = 5`（岩石）。

## 2. 要准备哪些素材

这是最容易被低估的部分。红警看起来「地形丰富」，靠的不是一张万能沙地贴图，而是**一整套互相咬合的瓦片组合**。
下面按「先能跑 → 再好看」分三级，你可以只做 P0 就开跑。

### 2.1 P0：能让地图看起来不像一张纯色纸（最少 14 张）

| 用途 | 张数 | 尺寸 | 说明 |
|---|---|---|---|
| 平地 | 4 | 56×28 | 同一块沙地的 4 个变体（不同噪点/龟裂），随机铺，避免明显重复 |
| 沙丘 | 3 | 56×28 | 比平地亮一档，带风纹；**必须画满整个菱形，四角不许透明** |
| 岩石 | 3 | 56×28 | 实心、暗，读作「不可通行」 |
| 矿脉 | 2 | 56×28 | 可通行，偏绿黄，上面再叠晶体 |
| 道路 | 2 | 56×28 | 压实的深色土路，边缘带车辙 |

> 四条硬性要求：① 菱形填满、**不要留透明角**（相邻格靠互相盖住消缝）；② 光源统一从左上，阴影右下沉；
> ③ 不要在图里画「格子边框」，会变成明显的棋盘；④ 每张的接缝两侧像素必须能对上 —— 做法是把瓦片当**无缝贴图**画，
> 或者让四角像素等于相邻瓦片同名像素。

### 2.2 P1：让地形「有边」（+ 约 60 张）

平地/沙丘/岩石/水域之间一旦直接拼接，边界会是一条硬直线，这是「像不像红警」的分水岭。

| 用途 | 张数 | 说明 |
|---|---|---|
| 两两过渡 | 每种地形组合 16 张 | 上/下/左/右四个边各「有/无」，共 2ⁿ 种角落组合。原版就是靠这个做的平滑接边 |
| 悬崖侧壁 | 4 方向 × 3 高度 = 12 | 高台侧面。也可以只做 1 张 56×16 的竖条纹由代码平铺拉伸 |
| 坡道 | 4 方向 × 2 | 上坡的斜面色，带明暗渐变 |
| 水岸 | 8 | 水面与沙的接触带（湿沙 + 白边） |

过渡瓦片的命名建议直接用位掩码：`clear_to_rock_1011.png`（上、右、下、左四位，1 = 该边接岩石）。
代码侧按邻格 `land` 差异查表，**这一步现在还没做** —— 见第 5 节「图集接入」。

### 2.3 P2：让地图「有东西」（+ 约 20 张）

| 用途 | 张数 | 尺寸 | 锚点 |
|---|---|---|---|
| 晶体矿簇 | 3（满/半/枯） | 64×64 | 底部中心 |
| 枯树 / 灌木 | 6 | 32×40 | 底部中心 |
| 碎石堆 | 4 | 32×24 | 底部中心 |
| 补给箱 | 1 | 32×32 | 底部中心 |
| 弹坑 / 履带痕 | 5 | 64×32 | 中心，贴地 |
| 边界装饰（岩壁、残骸） | 6 | 64×64 | 底部中心 |

物件是**后画的、按深度排序**的，所以它们的锚点必须在底部中心，否则会浮空或者被前排队友挡住。

### 2.4 如果你要直接用红警的 TMP

红警瓦片是 **60×30** 像素的 TMP：52 字节块头 + `zHeight` + `terrainType` + `rampType`，
60×30 的像素区实际存 900 个索引（行宽 4→60→4→0 的怪排布），调色板是 768 字节 6bit，索引 0 透明，16–31 是阵营重映射区。
我们的解析器已经写好了（`assets/scripts/assets/Tmp.ts` / `Shp.ts` / `Palette.ts`），
**尺寸按 60×30 读进来后按 56/60 缩放贴到 56×28 的格子上**。

⚠️ 只建议用自己画的、或明确授权的 TMP。参考项目 `RedAlert2-Android-main` 是 GPL-3.0，里面的美术/音频不能拿来用（代码可以学）。

## 3. 三条制作路线

### 路线 A：程序化（默认，已经在跑）

`MAPS` 里 `data` 字段为空的地图，是「种子 + 一组阈值」生成的：噪声出岩脊和沙丘 → 挖平两个基地 → 挖一条中路 → 镜像 → 铺矿。
优点是每局可以不同，缺点是永远长得像随机地形，做不出「双峡口」这种设计过的战场。

### 路线 B：编辑器手绘（推荐）

`tools/mapeditor.html` 的用法：

| 操作 | 效果 |
|---|---|
| 左键拖 | 用当前笔刷涂 |
| 右键拖 | 擦除（恢复平地/0 层/不阻挡） |
| 滚轮 | 缩放（3–28 像素/格） |
| 空格 / 中键拖 | 平移 |
| 地形按钮 | 选地表类型，笔刷大小 1/3/5/9 |
| 高度按钮 | 涂 0–3 层 |
| 标记·矿点 | 点一下放一个矿点（默认 4000 储量），右键在矿点上可删除 |
| 出生点 P0/P1 | 点一下移动基地中心 |

画布上的两个方框是 **7 格基地 apron 提示** —— 框内不能有岩石/水，否则基地建筑摆不下，
校验器会直接拒收。左下角实时显示可通行比例和警告。

导出后：

```bash
# JSON 放到 assets/maps/ 下
node tools/mapbuild.mjs          # 校验 + 生成 world/Maps.ts
```

想在主界面看到它，还要在 `Core.ts` 的 `MAPS` 里加一条（`data` 填 JSON 的 id）：

```ts
{ id: 'my-map', name: '我的地图', en: 'MY MAP', trait: '手工 · 一句话特点',
  data: 'my-map', seed: 1, rocks: 0, dunes: 0, lane: 0, ore: 1 },
```

（`seed/rocks/dunes/lane/ore` 这些是程序化参数，手绘图用不到，给 0 即可。）

### 路线 C：从 Tiled 或原版地图导入

- **Tiled**：建议只用它做「参考底图」，按 80×80 网格铺色块，然后 `node tools/mapgen.mjs` 里的写法批量转成我们的 JSON
  （Tiled 的 gid → `land` 是一张 6 项的映射表，写 20 行脚本即可）。
- **原版 .map**：`[IsoMapPack5]` 是 base64 + zlib 的瓦片流，我们已经有 LCW/zlib 读取能力，
  但还需要 `[Terrain]` 的 TileSet 映射表才能把 tile 编号对到图集。**只有在拿到完整 TMP 图集后才有意义**，否则导进来是空壳。

## 4. 一张地图的验收标准

`node tools/mapbuild.mjs` 会拒收以下情况（这些不是风格问题，是**打不了**）：

| 检查 | 为什么 |
|---|---|
| `size` 不等于 80、RLE 长度对不上 | 加载必然崩 |
| `land` 出现 5 以上的值、`height` > 3 | 渲染越界 |
| 出生点不在可通行地表 / 离边界太近 | 单位生不出来、镜头拉不出 |
| **两个出生点不连通**（8 向 + 不切角） | 一局永远打不到对面 |
| **任意矿点从任一方不可达** | 一方注定没钱，地图不可能公平 |
| **7 格基地 apron 里有岩石/水域** | 指挥核心 4×4 + 三栋附属建筑摆不下 |
| 出生点不在 0 层 | 基地会摆成阶梯状 |
| 可通行面积 < 25% | 不是地图，是走廊 |

`node tools/maptest.mjs` 再进游戏验一遍（这一层连不上就是寻路参数不一致）：

```
PASS  twin-gates 两个出生点之间有车辆通路
PASS  twin-gates 全部矿点可达        · 5 个矿点，不可达 0
PASS  twin-gates 采集链能产出        · 2 台采集车，60 秒产出 2400
```

注意第二条用的是**真寻路查询**（主战坦克的转向半径），不是格子洪水填充 ——
一格宽的缝在格子检查里是通的，坦克进不去，这种图必须当场拒掉。

## 5. 关卡设计准则（从原版抄来的几条硬经验）

1. **隘口至少 3 格宽**。1 格宽的缝只会让所有单位排队互撞；3 格刚好两辆车错身。
2. **每个基地至少 2 条出口**。唯一出口意味着一次堵路就整局结束。
3. **第一个矿点到基地 12–25 格**。太近没有护航压力，太远开局 40 秒全在赶路。
4. **中央必须有争夺价值**。做法：中央矿点储量是近点的 1.5–2 倍，或者中央高台（`height` 2–3）提供射程视野优势。
5. **对称优先**。手绘图也要保持点对称：左半画完，用镜像（`tools/mapgen.mjs` 的 `mirror()`）复制到右半，
   再手改细节。不对称的地图在联机里一定会被抱怨。
6. **高地不要连成一片**。`height` 差 ≥2 就是悬崖，天堑连片会让地图变成「谁先占山谁赢」。
7. **别把矿脉铺在隘口正中间**。采集车会被打仗的车辆堵死在里面（这是我们调了很久的坑）。

## 6. 图集接入：三处替换点

现在的画面是 `cc.Graphics` 程序化绘制的，`tiles` 只被当成调色变化用。接真图集时**只需要改三个地方**，
`EntityView`、寻路、迷雾、AI 全部不动：

| 位置 | 现在 | 换成 |
|---|---|---|
| `render/Views.ts` → `TerrainView.groundTile()` | 用 `land` 算颜色填菱形 | 按 `tile` id 取 `SpriteFrame` 贴到同样四个格角 |
| `render/Views.ts` → `TerrainView.paint()` 的物件部分 | `rockAt()` 程序化画石头 | 按 overlay 清单取贴图，底部中心锚点 |
| `render/Art.ts` → `drawBuilding()` | 程序化体块 | 已有 `paintHull/paintUnit` 的 manifest 管线，建筑走同一套 |

`tile` → 图集索引的映射写进 `art/manifest.json`（`tileset: { image, cell: 56, tiles: [...] }`），
`tools/assetcheck.mjs` 会校验每张图的尺寸和透明角。

## 7. 已内置的地图

| id | 名称 | 设计 |
|---|---|---|
| `flat` | **测试平面（当前唯一可选）** | 纯平面：无岩石、无水、无高度，只有两个基地和 5 个矿点。用来隔离"单位/美术/AI"的问题 —— 这张图上卡住一定是单位 bug，不是地形 |
| `twin-gates` | 双峡口 | 南北两道岩脊把战场切成三条路，中央 2 层台地，四条坡道 |
| `ring-lake` | 环湖 | 中央 168 格水域 + 环形公路，两个沙滩缺口，逼出绕行 |
| `mesa` | 台地 | 单一大高台（3 层）三条坡道，其余为开阔地，强调制高点 |
| `basin` `ridges` `dunes` `oasis` `flats` | 随机图 | 种子 + 阈值的程序化地图 |

> 菜单目前**只显示 `flat`**：你正在做自己的地图，一张干净平面比五张半成品更有用。
> 其余定义都还在 `Core.ts` 的 `MAPS_LIBRARY` 里，把 `MAPS` 的过滤条件改一行就能放回来；
> `?auto=1&map=mesa` 也仍然能加载，方便单独回归。

源码：`assets/maps/*.json`。改完记得 `node tools/mapbuild.mjs`。
